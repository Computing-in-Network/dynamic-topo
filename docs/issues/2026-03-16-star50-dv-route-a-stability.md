# star50 Route A DV 原型扩展与稳定性验证

## 背景

当前仓库已经完成 `10` 节点 Route A DV 原型：

- 中心控制器只向节点下发“当前直连邻居集合”
- 节点容器内运行 `dv_agent.py` 自主交换距离向量
- `star300lite_sim` 继续负责二层连通性约束

在 `10` 节点闭环可运行的基础上，需要进一步扩展到 `50` 节点，验证这套方案在更大规模下的可用性和基本稳定性。

## 目标

1. 在当前 `star300lite` 环境下拉起 `50` 节点 Route A DV 原型
2. 复用已有脚本能力，避免继续复制 `10` 节点专用脚本
3. 允许按节点规模和子集选择策略启动 Route A DV 原型
4. 完成一轮 `50` 节点启动、收敛和基本连通性验证

## 范围

1. 将 Route A DV 启动/停止流程参数化
   - 支持 `NODE_COUNT`
   - 支持子集选择策略
   - 支持按运行目录区分 `10` 节点和 `50` 节点场景

2. 新增 `50` 节点便捷启动/停止入口
   - `start_star50_dv_route_a.sh`
   - `stop_star50_dv_route_a.sh`

3. 文档补充
   - README 增加 `50` 节点启动、状态检查和停止方式

4. 运行验证
   - `50` 个 agent 全部成功启动
   - 至少抽样验证多跳路由已生成
   - 至少抽样验证 `10.255.x.x/32` 端到端可达

## 验收标准

1. 能通过单条命令启动 `50` 节点 Route A DV 原型
2. `manage_dv_agents.py --action status` 能看到 `50` 个 agent 进程
3. 抽样节点的 `ip route` 中能看到多跳 `/32` DV 路由
4. 抽样两点之间可以直接 `ping 10.255.x.x` 成功

## 注意事项

1. `50` 节点原型仍不能与 `300` 节点静态控制面并行运行
2. `50` 节点子集需要保证在当前实时拓扑下是连通的
3. 运行目录、日志和映射文件应与 `10` 节点场景隔离
