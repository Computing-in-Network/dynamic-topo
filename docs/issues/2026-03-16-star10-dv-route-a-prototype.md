# Issue: 10 节点 Route A DV 动态路由原型

## 背景

当前 `dynamic-topo` 已具备以下能力：

- 后端实时计算动态拓扑并通过 WebSocket 推流
- `push_sim_policy.py` 将实时链路关系下发到 `star300lite_sim`
- `push_static_routes.py` 将全局最短跳结果集中式下发为 300 节点静态路由

现阶段三层路由仍是“中心算全局路径、节点被动接收路由”的模式，不属于距离向量（Distance Vector, DV）动态路由。

## 目标

基于当前 `star300lite` 环境实现一个 **10 节点 Route A DV 原型**：

- 控制器只向节点下发“当前直连邻居列表”
- 路由不再由中心直接计算并写入
- 由每个节点容器内部运行 DV agent，自主交换距离向量并维护本机路由表

## 方案约束

1. 范围只覆盖 10 个节点，不扩展到 300 节点
2. 保留 `dynamic-topo` 和 `star300lite_sim` 现有实时拓扑/二层仿真链路
3. 不引入 FRR/RIP/OSPF，优先使用现有镜像中的 `python3` 做最小可用原型
4. 目标是验证“分布式 DV 收敛链路”，不是立即替代现有 300 节点静态路由方案

## 交付范围

1. 节点侧 DV agent
   - 在容器内运行
   - 使用 `lo /32` 作为本节点通告前缀
   - 使用 `veth_0` 作为 DV 报文和数据报文接口
   - 周期发送距离向量，触发式更新路由
   - 将收敛结果写入 Linux 路由表

2. 中心侧邻居下发器
   - 订阅实时拓扑
   - 仅对 10 节点子集提取当前直连邻居
   - 将邻居状态写入各节点容器，供 DV agent 读取

3. 原型启动/停止脚本
   - 一键完成 10 节点映射准备
   - 部署/启动 DV agent
   - 启动邻居下发器
   - 停止并清理相关进程

4. 文档
   - README 增加 Route A DV 10 节点原型说明
   - 明确与现有 `push_static_routes.py` 的区别

## 验收标准

1. 在 10 个节点范围内可启动 DV agent，并持续运行
2. 中心只下发直连邻居，不直接下发全局路由
3. 节点收到邻居向量后，能够在容器内写出到其他节点 `lo /32` 的动态路由
4. 拓扑变化后，邻居变化会传递到各节点，路由表能发生收敛更新
5. 提供最小观测手段：
   - agent 日志
   - 当前 DV 路由快照
   - 容器内 `ip route` 验证方式

## 风险与注意事项

1. Route A 不是完全纯粹的 DV
   - 中心仍然下发“当前直连邻居集合”
   - 但不再直接下发全局路径

2. 动态拓扑变化较快，DV 可能出现震荡
   - 需要最小更新周期、路由超时、垃圾回收等保护机制

3. 需要避免经典 DV 问题
   - 环路
   - count-to-infinity
   - 路由陈旧项滞留

4. 当前前端主要展示中心路由快照
   - DV 原型阶段以容器日志和容器内路由表验证为主
